# T04.04. Ранжировать результаты и объединять слова по И

**Исполнитель:** 9B-модель; результат проверяет человек.

## Задача

## Сделать

1. Каждый токен запроса обязан совпасть хотя бы в одном поле вещи
2. Exact выше stemming выше fuzzy; title важнее description/notes по фиксированным весам D05
3. Уточнённое положение prefix брать из контракта
4. Пустой запрос возвращает галерею
5. Пересекать с GalleryQuery без потери ранга по D12

## Готово, когда

- Два слова в разных полях одной вещи дают результат
- Вещь с одним из двух слов не проходит
- Проверены exact/stem/fuzzy и веса полей
- При одинаковом score порядок стабилен
- Фильтры ограничивают поиск

### Общие границы

Это проект Inventory: одно локальное macOS-приложение, Flutter/Dart + SQLite, русский UI. inventory_core — чистый Dart: без package:flutter и dart:ui. UI обращается к сервисам ядра, а не к SQL. UUID v4 — строки; время — UTC Unix milliseconds, отображение локальное. Clock и IdGenerator внедряются для тестов. Все записи БД транзакционны, foreign_keys включается на каждом соединении. Исключённые функции из §2.2 не добавлять. У вещей и мест ровно одно обязательное фото. Вещи, статусы и люди физически не удаляются. Перед реализацией должен существовать утверждённый API_CONTRACT.md; имена ниже — предложения для его подготовки, а не повод менять уже согласованный API.

### Поиск

SearchDocument хранит itemId и поля отдельно с указанием источника: name, description, notes, tags, названия текущего места и всех его предков, имена всех людей из give/return, включая архивных. Индекс — в памяти в чистом Dart, без FTS/нативных токенизаторов SQLite. Нормализация lower + ё/е + пунктуация, русский Snowball, латиница согласно T00.02. SearchEngine.search(query) возвращает ранжированные itemId; несколько слов = AND, пустой запрос = все вещи. Точное совпадение выше стемминга и нечёткого, название весомее описания/заметок. Префикс и Дамерау–Левенштейн/триграммы реализуются по фиксированным правилам D05. Результат пересекается с GalleryQuery. После commit сервис публикует MutationEvent, индекс обновляется с учётом зависимых вещей.

### Вещи, теги и галерея

ItemService: create / updateDetails / get / list; отдельного delete нет. Create выбирает активный default_status_id и не создаёт историю. UpdateDetails не принимает statusId: статус меняется отдельной командой. quantity — integer ≥1; название ≤200; photo обязателен; placeId nullable. TagKey = trim → collapse spaces → lower → ё/е; первое написание хранится в name, длина ≤50. Вещь имеет каждый тег не более одного раза; неиспользуемые теги удаляются после успешной операции. GalleryQuery: текст, место с потомками или «Без места», множество статусов включая архивные, все выбранные теги (AND), сортировка и направление. Фильтры применяются также к поиску.

## Релевантные пункты исходного ТЗ

### 8.2. Реализация
- Только на стороне Dart, без расширений SQLite. На объёме в сотни вещей индекс строится в памяти при запуске и точечно обновляется при изменениях.
- Нормализация: нижний регистр, ё→е, удаление пунктуации.
- Токенизация, русский стемминг (Snowball), для латиницы английский стемминг или без стемминга.
- Совпадения: по основе слова, по префиксу, а также нечёткие: расстояние Дамерау-Левенштейна с порогом, зависящим от длины слова, и/или сходство по триграммам.
- Ранжирование: точное совпадение выше стемминга, выше нечёткого; совпадение в названии весомее, чем в описании и заметках. Несколько слов в запросе объединяются по «И».
- Пустой запрос возвращает все вещи (как галерея).
- Допустимые параметры порогов агент подбирает сам, чтобы выполнялись критерии ниже без заметного количества ложных срабатываний.

### 6.8. Галерея
Режим 1, **сетка**:
- Квадратные превью с обрезкой по центру, под фото название; на плитке небольшая метка статуса.
- Ползунок размера плитки (мелко, средне, крупно), значение запоминается между запусками.
- Сортировка: по умолчанию новые сверху; доступны по названию и по дате добавления (с направлением).
- Фильтры: по месту (**включая вложенные места**; отдельный пункт «Без места»), по статусу (несколько, включая архивные), по тегам (несколько; вещь должна иметь все выбранные теги). Последние выбранные фильтры, сортировка и режим запоминаются между запусками, есть кнопка «Сбросить фильтры».
- Все вещи показываются всегда, скрытия по статусу нет.
- Превью загружаются лениво; на нескольких сотнях вещей прокрутка плавная.

Режим 2, **«По местам»**:
- Навигация внутрь места: показываются вложенные места (с фото) и вещи этого места. Сверху хлебные крошки, клик по сегменту ведёт на этот уровень.
- Первым в корне идёт виртуальный раздел «Без места» (вещи без места), вне алфавитного порядка.
- Порядок: сначала вложенные места, затем вещи; внутри групп по названию без учёта регистра с естественным порядком чисел («Полка 2» раньше «Полка 10»).
- Из этого режима создаются места («Добавить место») и вещи (с предзаполненным местом).
