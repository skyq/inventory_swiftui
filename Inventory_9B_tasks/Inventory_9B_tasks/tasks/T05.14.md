# T05.14. Напоминать о ручном бэкапе

**Исполнитель:** 9B-модель; результат проверяет человек.

**Зависимости:** [T05.13](T05.13.md).

**Исходник:** §4.3, §10.2 [TZ_inventory_mvp.md](../00_SOURCE/TZ_inventory_mvp.md).

**Область изменений:** BackupReminderService; app UI hint; preferences tests.

## Задача

Показать отключаемое напоминание после 30 дней без успешного экспорта.

## Что предоставить модели

Эту карточку целиком; утверждённые части API_CONTRACT.md и DECISIONS_APPROVED.md для перечисленных модулей; текущие интерфейсы/реализации и тесты только из области изменений; последний HANDOFF.md. Прочитать результат зависимостей по существующему коду, а не сочинять его по описанию. Если код или утверждённый контракт не приложен и недоступен через инструменты, вернуть BLOCKED с точным списком нужных файлов.

## Границы выполнения

Выполни только эту задачу. Не начинай следующую, не переписывай соседние модули и не меняй публичные контракты. Не добавляй функции вне MVP. Имена и папки в области изменений уточняются утверждённым API_CONTRACT.md; не создавай параллельную реализацию уже существующего сервиса. Если контракт противоречит ТЗ или требуется новое решение, останови зависимую часть и верни BLOCKED с причиной; не принимай решение молча.

## Сделать

1. Использовать Clock и external preferences lastSuccessfulExport/reminderEnabled
2. Если экспорта не было или прошло более 30 дней, показать ненавязчивое сообщение
3. Дату обновлять только после успешного сохранения архива
4. Не создавать расписаний автокопирования или сетевых запросов

## Готово, когда

- Нет экспорта/29/30/31 день проверены по утверждённой границе
- Неудачный экспорт не сбрасывает срок
- Отключение сохраняется между запусками
- Настройка и дата не попадают в архив

## Рабочий контекст

> Ниже — предложения для утверждённого контракта, а не замена исходного ТЗ. При расхождении сначала согласовать контракт.

### Общие границы

Это проект Inventory: одно локальное macOS-приложение, Flutter/Dart + SQLite, русский UI. inventory_core — чистый Dart: без package:flutter и dart:ui. UI обращается к сервисам ядра, а не к SQL. UUID v4 — строки; время — UTC Unix milliseconds, отображение локальное. Clock и IdGenerator внедряются для тестов. Все записи БД транзакционны, foreign_keys включается на каждом соединении. Исключённые функции из §2.2 не добавлять. У вещей и мест ровно одно обязательное фото. Вещи, статусы и люди физически не удаляются. Перед реализацией должен существовать утверждённый API_CONTRACT.md; имена ниже — предложения для его подготовки, а не повод менять уже согласованный API.

### Архив и безопасная замена

BackupCodec v1: manifest.json(format_version=1, app_version, exported_at, counts), data.json со всеми 9 таблицами, photos/, thumbs/. Не включать _safety/, logs/, preferences, lock-файлы. «9 таблиц» = places, statuses, people, items, tags, item_tags, status_changes, transfers, settings. BackupValidator не меняет активные данные. ValidatedBackup — только проверенный staging. Импорт: полная проверка → подтверждение числа вещей → последняя safety-копия → остановка операций → подготовленная замена → проверка/открытие → возобновление. При сбое восстановить старое состояние. Временные папки и журнал не смешивать с _safety; до успешной замены прежнюю копию не уничтожать. SQL-транзакция не покрывает файловую систему: соблюдать утверждённый D01. Импортировать историю INSERT в новую staging-БД с работающими триггерами, а не DELETE из живой истории.

### Интерфейс

Слева: Галерея / По местам / Люди / Статусы / Теги / Данные. Поиск всегда сверху; карточка вещи справа, формы модальные. Строки UI и перевод доменных ошибок — в русском ARB; технические детали в лог. Светлая/тёмная тема системные, базовые фокус клавиатуры и масштабирование текста. Разрешены Cmd+K, Cmd+N, Cmd+W, Esc, стандартные меню macOS; Cmd+V работает как источник фото в форме. Новых хоткеев и контекстного меню не добавлять. UI-настройки в PreferencesStore, настройки default/transfer/return_status_id — в таблице settings. Длительные операции показывают прогресс и не блокируют UI.

## Релевантные пункты исходного ТЗ

### 4.3. Данные на диске
Папка данных (по умолчанию `~/Library/Application Support/Inventory/`, меняется в настройках):
```
inventory.db
photos/<uuid>.jpg
thumbs/<uuid>.jpg
logs/app.log
_safety/before-import/       # копия хранилища перед импортом (база и фото)
_safety/before-migration/    # копия файла базы перед миграцией
```
Путь к папке данных хранится вне этой папки (в `shared_preferences`).

Настройки интерфейса (размер плитки, сортировка, фильтры, дата последнего экспорта, включено ли напоминание о бэкапе) хранятся локально в `shared_preferences` и в архив не попадают. Настройки, связанные с данными (статусы по умолчанию), хранятся в таблице `settings` и попадают в архив.

### 10.2. Целостность и сбои
- Все записи идут в транзакциях; многошаговые операции (передача, возврат, объединение тегов, перенос данных) выполняются одной транзакцией.
- При запуске выполняется `PRAGMA integrity_check`. Если база повреждена, приложение сообщает об этом и предлагает восстановиться из ручного бэкапа; пустую базу не создаёт.
- Ошибки: понятное сообщение на русском пользователю, подробности в `logs/app.log` (ротация, например 5 файлов по 1 МБ).
- Напоминание о бэкапе, если последний экспорт был более 30 дней назад (или его не было); отключается в настройках.

## Ответ исполнителя

Верни: DONE или BLOCKED; что изменено; список файлов; фактические команды проверки и их результат; что проверено вручную на Mac; отклонения от ТЗ и нерешённые вопросы. Не называй тесты пройденными, если их не запускал. Для кода добавь/обнови тесты бизнес-правил и отказов, перечисленных в этой карточке; не пиши тесты, просто повторяющие реализацию. Для документа/приёмки проверь содержимое и ссылки без бессмысленных unit-тестов. Обнови HANDOFF.md по шаблону и запись своей задачи в RUN_LOG.md. DONE — только после выполнения критериев; незапущенные обязательные проверки означают BLOCKED. На карточке приёмки этапа выполнение проверок не заменяет подтверждение владельца.
