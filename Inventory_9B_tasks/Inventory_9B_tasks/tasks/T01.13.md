# T01.13. Запретить циклы при перемещении мест

**Исполнитель:** 9B-модель; результат проверяет человек.

## Задача

Перемещать поддерево без циклов и без обхода защиты через прямой вызов сервиса.

## Что предоставить модели

Эту карточку целиком; утверждённые части API_CONTRACT.md и DECISIONS_APPROVED.md для перечисленных модулей; текущие интерфейсы/реализации и тесты только из области изменений; последний HANDOFF.md. Прочитать результат зависимостей по существующему коду, а не сочинять его по описанию. Если код или утверждённый контракт не приложен и недоступен через инструменты, вернуть BLOCKED с точным списком нужных файлов.

## Границы выполнения

Выполни только эту задачу. Не начинай следующую, не переписывай соседние модули и не меняй публичные контракты. Не добавляй функции вне MVP. Имена и папки в области изменений уточняются утверждённым API_CONTRACT.md; не создавай параллельную реализацию уже существующего сервиса. Если контракт противоречит ТЗ или требуется новое решение, останови зависимую часть и верни BLOCKED с причиной; не принимай решение молча.

## Сделать

1. Проверять self-parent и всех потомков рекурсивным запросом в доменной операции
2. Проверку и UPDATE выполнять одной транзакцией
3. Сохранять идентификаторы и связи потомков
4. Предоставить список недопустимых родителей для формы

## Готово, когда

- A→A и A под собственного внука отклоняются
- Перемещение к другому корню и в NULL работает
- Потомки остаются в поддереве, путь обновляется вычислением
- Прямой вызов без UI не обходит проверку

### Общие границы

Это проект Inventory: одно локальное macOS-приложение, Flutter/Dart + SQLite, русский UI. inventory_core — чистый Dart: без package:flutter и dart:ui. UI обращается к сервисам ядра, а не к SQL. UUID v4 — строки; время — UTC Unix milliseconds, отображение локальное. Clock и IdGenerator внедряются для тестов. Все записи БД транзакционны, foreign_keys включается на каждом соединении. Исключённые функции из §2.2 не добавлять. У вещей и мест ровно одно обязательное фото. Вещи, статусы и люди физически не удаляются. Перед реализацией должен существовать утверждённый API_CONTRACT.md; имена ниже — предложения для его подготовки, а не повод менять уже согласованный API.

### Места

PlaceService: create / update / move / deleteEmpty / path / descendants / children. Конкретные DTO утверждаются в T00.03. name обязателен, ≤200 символов, parentId nullable. Путь вычисляется из иерархии. Дубли у одного родителя разрешены после предупреждения. Нельзя выбрать самого себя или потомка; сервером здесь является доменный сервис, UI-фильтра недостаточно. Удаление запрещено при прямых детях или вещах; ошибка содержит оба числа. Перенос сохраняет всё поддерево без изменения его id. После успешного удаления пустого места убирается его собственная пара фото. Естественная сортировка: «Полка 2» перед «Полка 10».

## Релевантные пункты исходного ТЗ

### 6.1. Места
- Создание, редактирование (название, описание, фото, родитель), перемещение вместе со всем содержимым.
- Поля: название (обязательно, до 200 символов), описание, фото (обязательно), родитель (необязательно; пусто = корневое место).
- Глубина иерархии не ограничена.
- **Защита от циклов**: нельзя назначить родителем само место или любого его потомка. Проверка в доменном слое (рекурсивный запрос) и тест; в интерфейсе недопустимые варианты не предлагаются.
- **Удаление**: только если в месте нет вещей и вложенных мест. Иначе удаление запрещено, приложение показывает, что именно мешает (количество вещей и вложенных мест), и предлагает их переложить. При удалении места удаляются его фото и превью.
- Путь места (`Спальня / Шкаф / Верхняя полка`) всегда вычисляется из иерархии, нигде не хранится.
- Дублирование названия среди мест одного родителя разрешено, но приложение показывает предупреждение.

## 13. Тесты (обязательный минимум)

Автотесты пишутся и запускаются на каждом этапе (`dart test` для ядра, `flutter test` для UI, один интеграционный smoke-тест на macOS к концу этапа 5).

- Иерархия мест: цикл, перемещение поддерева, удаление пустого и непустого места.
- Вещи: валидации, количество ≥ 1, обязательность фото, смена статуса на тот же запрещена.
- Транзакции передачи и возврата, откат при сбое.
- Неизменяемость истории.
- Теги: нормализация, переименование, объединение, автоудаление.
- Статусы и люди: архивация, ограничения.
- Поиск: примеры из 8.3, негативные тесты, производительность.
- Экспорт и импорт: round-trip, невалидные архивы, откат.
- Миграции: из каждой предыдущей версии схемы (начиная со второй версии).
- Фото: ориентация, ресайз, превью, откат файлов при сбое.

DONE — только после выполнения критериев; незапущенные обязательные проверки означают BLOCKED. На карточке приёмки этапа выполнение проверок не заменяет подтверждение владельца.
